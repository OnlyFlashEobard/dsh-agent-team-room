# Agent Team Room · 智能体团队

一个真正的多 Agent 协作界面插件，安装后出现在 DSH Web GUI 左侧栏，打开后是一个独立页面。

仓库：https://github.com/OnlyFlashEobard/dsh-agent-team-room

- **协作空间**：写下任务目标 → 团队成员按轮次持续发言，直到主 Agent 判定任务已交付或你主动停止；每个成员都能看到前面的对话，你可以随时插话。
- **团队设置**：为每个 Agent 配置名称、角色、头像表情与颜色、模型服务、模型、温度、人设（系统提示词），启用/停用或增删成员；全局配置团队名称、收尾总结者、自动组队。
- **成员详情 / 运行面板**：右侧显示当前阶段（协作 / 交付判定 / 总结）、当前发言者、轮次、耗时、Token 用量与发言分布，点击任意成员可查看其模型与人设。
- **自动组队**：主 Agent 会先分析任务内容与难度，再决定用几个子 Agent、各自角色/人设/模型/温度。既可在任务栏点「AI 组队」先内联预览方案，也可打开「按任务自动组队」让每次协作前自动规划。

所有发言都由配置的模型真实生成（通过 Host 的 `llm.stream`），不是占位文本；对话会流式写入并在页面轮询展示，团队配置与最近一场协作记录持久化到 `~/.dsh/agent-team-room.json`。

## 运行到交付为止（无轮次上限）

协作不是固定轮数，而是一个持续循环：

1. 成员依次发言；
2. 一轮结束后，主 Agent 读取本轮对话与项目进展摘要，做**交付判定**：`delivered`（是否已完成到可交付）、`progress`（本轮是否有实质进展）、`reason`、`nextFocus`；
3. 未交付 → 用 `nextFocus` 作为下一轮重点继续协作；已交付 → 指定成员输出**最终交付说明**并结束。

因此没有「最多几轮」的限制，只有三种结束方式：**判定交付**、**你点停止协作**、或连续基础设施失败（例如连续三次无法完成交付判定）导致中断。运行中会显示「第 N 轮」与当前阶段；连续多轮没有进展时会给出提示但不会自动停止。长时间运行的进展摘要会被压缩进判定输入，避免上下文无限增长；DSH 关闭导致的中断会在记录中标记为「已停止」。

## 两种组队方式

1. **人工配置**：在「团队设置」里手写每个成员；关闭「按任务自动组队」时，协作严格使用当前配置。
2. **主 Agent 自动配置**：打开「按任务自动组队」后，每次开始时先由主 Agent 输出组队方案（成员数随难度变化：简单 1-2 人、一般 3 人、复杂 4-5 人，最多 6 人，并决定收尾者），保存后再执行协作；对话流里会出现一张「主 Agent · 自动组队」卡片说明理由与名单。
   也可以在任务栏点「AI 组队」：内联预览（理由、成员、模型、收尾者）后选择「只采用配置」或「采用并开始协作」，不弹窗、不打断操作。

主 Agent 使用的模型就是当前 profile 的默认模型；成员的 provider/model 会校验为该 profile 已启用的服务，不合法时回落到默认模型。

## 给会话主 Agent 的工具

插件还注册了 `agent_team_room` 工具，当前会话的主 Agent 可以：

- `plan`：按任务内容与难度给出组队方案（`apply: true` 时直接保存为团队配置）；
- `start`：自动组队、保存并立即开始一次真实协作（随后持续到交付或停止）；
- `status`：读取当前或最近一次协作状态（轮次、阶段、是否已交付）。

页面与工具共用 Host 中同一套组队与运行逻辑。

## 安装与使用

在 DSH 中以 bundle 方式安装本目录（`plugin_manager` → `install_bundle`），或把目录链接到 profile 的 `node_modules` 后重启。安装后左侧栏出现「智能体团队」入口。

1. 打开「智能体团队」→「团队设置」，为成员选择服务与模型（默认沿用当前默认模型），或直接开启「自动组队」。
2. 回到「协作空间」，输入任务目标，点「开始协作」；想先看方案就点「AI 组队」。
3. 成员持续协作；可随时插话；任务交付后自动收尾，或你主动「停止协作」。
4. 结束后由收尾成员给出交付说明；「清空记录」移除上一场内容。

## 数据与接口

- 配置与最近一场记录：`~/.dsh/agent-team-room.json`
- 同源接口（仅本机可访问）：`/api/agent-room/{meta,state,config,plan,start,stop,message,reset}`

## 当前范围

团队成员通过模型协作产出方案、评审与总结，暂未向成员开放文件/终端等工具执行能力；若需要成员直接操作代码与文件，可在后续版本把每个成员升级为真实的子会话 Agent。交付判定是模型判断，不等于自动执行验收；需要硬性验收时可在任务目标里写明验收命令与标准。
