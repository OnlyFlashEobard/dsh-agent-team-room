# Agent Team Room · 智能体团队

一个多 Agent 协作工作室插件，安装后出现在 DSH Web GUI 左侧栏，打开后是独立页面：配置 Agent、下达任务、观看 Agent 之间的协作，直到主 Agent 判定交付或你主动停止。

仓库：https://github.com/OnlyFlashEobard/dsh-agent-team-room

## 能力

- **协作空间**：任务目标 + 可选验收标准；成员按编排方式持续发言，实时流式展示；可随时插话、暂停、继续或停止。
- **交付判定**：每轮结束由主 Agent 按任务目标与验收标准判定是否交付；未交付时给出下一轮重点，已交付时由收尾成员输出交付说明。
- **团队设置**：每个 Agent 的名称、角色、头像/颜色、服务、模型、温度、max tokens、推理强度、人设；启用/停用、增删、上下移动发言顺序；团队名称、收尾成员、自动组队、主 Agent 模型、编排模式、单次调用超时、成员工作模式、工作区。
- **自动组队**：主 Agent 按任务难度决定成员数量与配置；任务栏可点「AI 组队」内联预览后采用，或开启「按任务自动组队」每次先规划再协作。自动规划/采用前的阵容会保存，可一键恢复。
- **运行历史**：保留最近多场协作，可打开查看、继续未完成场次、导出、删除；当前场次与历史场次分开显示。
- **交付物**：导出 Markdown；选择工作区后可把记录保存为 `agent-team-room-<run>.md`。
- **工作区上下文**：读取所选目录的结构与关键文件（README/AGENTS.md/package.json 等）作为团队上下文。
- **两种成员模式**：`对话` 只调用模型；`真实执行` 为每个成员创建带工具的短子会话（实验性，可能触发工具审批，并会在工作区内读写）。
- **三种编排**：顺序轮询、主 Agent 点名下一轮成员、同轮并行。

所有发言都是配置模型的真实输出。配置与运行历史按 DSH profile 隔离，保存在当前 profile 目录的 `agent-team-room.json`。

## 运行方式

协作没有轮次上限：成员发言 → 主 Agent 交付判定 → 未交付则按 `nextFocus` 继续，已交付则总结结束。结束方式只有：

1. 判定交付；
2. 用户暂停/停止（暂停后可继续，停止后可「继续上一场」）；
3. 连续基础设施失败（连续三次判定失败或连续两轮无人产出）导致中断。

暂停会等当前轮结束后生效；恢复会从已保存的记录继续，不会重新跑前面的轮次。长任务的上下文只带最近发言与项目进展摘要，避免无限膨胀。

## 验收标准

任务栏的「验收标准」会进入判定与总结：主 Agent 逐条核对；有明确验收标准时，不会仅凭提纲宣布交付。留空则由主 Agent 按任务目标自行判断。

## 主 Agent 模型与容错

团队设置里可选「主 Agent 服务/模型」，用于自动组队与交付判定；留空跟随 profile 默认模型。组队/判定调用失败时会尝试回退到收尾成员或团队成员的模型；单次调用超过配置的超时时间会记为失败并继续（成员回合失败会记录到消息里）。

## 给会话主 Agent 的工具

`agent_team_room` 工具支持：

- `plan`：按任务与难度给出组队方案（`apply: true` 时保存）；
- `start`：自动组队、保存并立即开始协作；
- `status`：读取当前/最近一场状态。

## 安装与使用

以 bundle 方式安装本目录（`plugin_manager` → `install_bundle`），或链接到 profile 的 `node_modules` 后重启。安装后左侧栏出现「智能体团队」。

1. 「团队设置」配置成员与主 Agent 模型；或开启「自动组队」。
2. 「协作空间」填写任务目标与验收标准 → 开始协作，或先「AI 组队」预览。
3. 随时插话；需要停下来讨论时点「本轮后暂停」，恢复用「继续上一场」。
4. 在「运行历史」查看/导出/继续之前的场次。

## 数据与接口

- 当前 profile 下 `agent-team-room.json`（旧版 `~/.dsh/agent-team-room.json` 会一次性迁移）
- 同源接口：`/api/agent-room/{meta,state,config,plan,start,pause,resume,stop,message,reset,history/*,roster/undo,model-info,export,save}`

## 开发

```bash
node --check index.js && node --check client.js
node test-engine.mjs
```

`test-engine.mjs` 使用假模型覆盖：多轮直到交付、验收标准、暂停/恢复、历史、阵容快照、点名编排、工作区上下文、缺模型成员、真实执行模式的 subagent 链路。

## 已知限制

- 真实执行模式依赖当前 profile 的 subagent 服务，并使用当前活动会话作为父级；可能继承父会话上下文，工具调用可能触发审批。它适合需要读写工作区的场景，日常讨论用对话模式即可。
- 交付判定是模型判断，不会自动执行验收命令；需要硬性验收时请把命令/标准写进验收标准，或使用真实执行模式让成员自行验证。
- 调用来源校验目前仅限回环地址（未做 Origin/CSRF 防护），请只在本机使用。
